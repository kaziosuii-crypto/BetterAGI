# ProAct 框架分析（论文原文 → 可迁移结构）

> 依据：Zeyi Zhang, Zixi Kang, Ruijie Zhao, Yusen Feng, Biao Jiang, Hanyu Ji, Libin Liu. *ProAct: A Dual-System...*（arXiv 2602.14048v2，SIGGRAPH Asia 2026 Journal Track，2026-09-03 修订，北京大学）。
> 全文抓取件：`_diag/proact_paper.txt`（HTML：`_diag/proact_paper.html`）。本文件所有行号引用均指该抓取件。
> 需求文档对它的定位：`Docs/requirements/REQ-2026-11-04-dual-system-multi-game.md:4` ——「仅借鉴架构思想，不引入人形机器人动作生成部分」。

## 1. 它到底在解决什么问题

ProAct 要解决的不是「反应快」，而是**主动性（proactivity）与流畅性的冲突**（:319-321）：

- 人形社交机器人如果只会被动应答，就永远等不到「该主动做点什么」的时刻；
- 但如果让慢思考模型不停地插手，就会打断对话、显得机械；
- 同时，交互越长，历史越长，慢思考模型的推理时延越长——**时延会随会话长度漂移**，这是致命的。

所以它的两个技术靶心是：**① 让慢思考的时延与交互长度解耦；② 让「什么时候动手」有一个可解释、可调、可消融的门控**。

这两点与我们做「AI 像真人一样玩游戏」是同一个问题：真人在游戏里也是「反应快的手」+「偶尔停下来想」+「大部分时间不该乱动」。

## 2. 三段式结构（原样拆）

### 2.1 Behavioral System（System-1，快）

- **流式 omni-modal LLM**（GPT Realtime 类）：回合制流式，VAD 检测说话结束，**支持被打断**；
- **流式 flow-matching 动作生成器**：把语音/语义直接变成连续人形动作；
  - 硬约束：**每个 chunk 的生成时间必须小于该 chunk 的播放时长**（实时性由架构保证，不靠调参）；
  - overlap-and-cache 保证 chunk 之间的时序连续（:435 附近）；
  - **Disentangled ControlNet** 分支：把慢系统给的语义意图（"抬手打招呼"）注入动作流；没有意图时该分支零初始化，**自动回落为纯音频驱动**（:377-383）。

> 关键设计思想：**快系统的默认状态是「被驱动的被动响应」，主动干预是叠加进去的稀疏信号**。这正好对应我们想要的「大部分时间在自然游玩，偶尔抬头做点有性格的选择」。

### 2.2 Cognitive System（System-2，慢，与快系统并行）

不是一个大 LLM 直接想，而是**两个组件在一个 cycle 内并行**，且都只吃上一 cycle 的产出（:323-325）：

| 组件 | 输入（窗口） | 输出 | 目的 |
| --- | --- | --- | --- |
| **Context Encoder** | 最近 **5 个 cycle 间隔**的对话转写 + 本轮间隔内**均匀采样 3 帧** + 上一轮 plan | 更新后的 **有界 memory bank** | 把「越来越长的历史」压成「恒定大小的状态」 |
| **Behavior Planner** | 上轮以来的对话 + **最新单帧** + memory bank + 上轮 plan | 一组 proactive action plan | 用最新证据做「此刻要不要动」的决策 |

**非对称输入窗口**是这里最容易被忽略的设计（:338）：编码器看「长历史 + 多帧」换压缩质量，规划器只看「最新一帧 + 短转写」换低延迟。两边各自最优，而不是把长上下文同时塞给两者导致规划器变慢。

**memory bank 三层，每层一句话**（:334）：

1. **user analysis**（Theory of Mind）：对方可观察的外表 + 推断的信念/欲望/行为意图；
2. **situation tracking**：发生了什么事、环境变化、**未完成的任务**；
3. **robot action history**：自己刚才做过什么主动行为（用于**防重复干预**）。

> 「每层一句话」是拿「完美回忆」换「恒定推理时延」的显式交易（:334 原文：*trades perfect recall for consistent inference speed*）。

### 2.3 决策门控：Motivation Assessment（这篇论文真正的贡献）

五维打分，每维 **1–5**（:344-362）：

| 维度 | 含义 |
| --- | --- |
| Visual Scene Changes | 环境是否发生了需要注意的变化 |
| User Intent Signals | 对方行为里是否有「需要我」的显式/隐式线索 |
| Conversation State | 对话流走到哪了，此刻插话合不合适 |
| Social Protocol Requirements | 社交礼节/仪式要求（打招呼、送客…） |
| Emotional Response Needs | 对方情绪状态，需要共情/回应 |

触发规则（:364 + 附录 F 的 planner prompt :2044-2056）：

- `motivation_score = MAX(五个维度)`；
- **任一分 ≥ 4（τ=4）才启动**主动行为推理；全 < 4 直接 early-exit，把所有 proactive 行为置空；
- τ 的取舍是显式的：低了「过度打断」，高了「错过机会」。

### 2.4 三通道注入 + 两级克制（最该抄的部分）

plan 出来后分三路注入快系统（:369-381）：

1. **Dialogue Context** → 往 omni LLM 里注 prompt（决定说什么、打断不打断）；
2. **Gesture Intention** → 文本形式的 `身体部位 + 动作` 描述，走 ControlNet 进动作生成器；
3. **Locomotion Control** → 速度/朝向指令（前进 0.3–0.5m、转向 15–45°）。

**两级克制**（:383，附录 F :2098-2104）：

- **通道级**：Dialogue 通道**只有某维度打到最高分 5** 才允许激活（`should_interrupt = true ONLY if motivation_score >= 5`），且明确禁止「对方正说到一半就打断」，要求等自然停顿；只有安全/紧急纠错才允许抢占；
- **行为级**：per-behavior **action-history check**，阻断「最近历史里已经出现过的任何 gesture / phrase / turn」。原文说这一条在实际运行中**消除了 stuttering 与冗余干预**。

> 这两级克制，比「双系统」本身更值得迁移——它解决的是「系统有能力做，但**该不该做**」的判断。我们目前的实现里，这一层几乎完全是空的。

### 2.5 循环形态：continuous streaming cycles

每个 cycle 在**上一个结束的瞬间立即开始**（:325），不等事件、不等用户输入。这意味着：
- 慢系统的节奏是**稳定的粗时钟**（cycle 级），不是事件驱动；
- 快系统永远在线，慢系统的产出是「稀疏注入」。

## 3. 论文给出的量化证据

评测集 **ProActBench**（positive cases + **negative-trap** 反例，同一输入对每个系统重放，每例重放 3 次，3 名标注者）（:586-606）：

| 指标 | 数值 | 出处 |
| --- | --- | --- |
| Precision | 0.878 | :613, :629 |
| Recall | 0.800 | :613, :630 |
| 标注者估时延 | 3.7 s | :631 |
| 质量分（Gesture / Dialogue / Loco） | 4.34 / 4.21 / 4.50 | :632-634 |

**消融**：去掉 Motivation Assessment、或把它换成 Direct LLM（GPT-5.1 直接判断「现在该不该主动」）都会明显掉分；flow-matching 单 5s chunk 满足实时约束，而 diffusion 基线违反。

**错误分析**（:1809, :1815-1824）——这部分对我们设计失败处理最有价值：

| 漏报原因 | 占比 |
| --- | --- |
| weak signal（信号太弱没到阈值） | 32 cycles / 1.8% |
| **memory failure（记忆缺失/错误导致没认出需求）** | 16 cycles / 0.9% |
| system failure（推理模型本身出错） | 4 cycles / 0.2% |

**负例陷阱**（:1826-1858）：10 组陷阱里 8 组能在 3 次重放中至少 2 次正确保持沉默；最难的两组是「长时间沉默」与「熟悉的自主型访客」，说明**模糊的面部/沉默线索会被过度解读**。

> 结论：即使在这篇论文里，**主要失败来源也是「记忆坏了」而不是「模型不聪明」**。这对我们当下的诊断是一个强提示：把记忆闭环修好，收益可能大于换更大的模型。

## 4. 论文自己承认的局限（:1882-1901）

1. **触发是固定间隔 + 阈值判据**，会漏掉转瞬即逝的机会，也会误触发；作者提出「从交互数据里学自适应触发」作为未来工作（:679）；
2. **ProActBench 单环境、每例只有一个决策点**，无法覆盖「重复干预、cooldown、长程累积」；
3. **memory bank 是 session 级的**，交互结束即清空，**没有跨 session 的用户画像落盘**；
4. 行为抑制是「规划器层去重」，不是系统性的「策略学习」。

> 第 3 条对我们尤其重要：我们要的恰恰是**跨 session 长期记忆**（键位、地图、教训）。ProAct 没有解决这个问题，我们的需求文档（Graphiti）在这一点上是**超出**论文的，不能因为「对齐 ProAct」而降级。

## 5. 迁移到「玩游戏」：概念映射表

ProAct 的对象是「人形机器人 + 一个人类对话者」，我们是「游戏角色 + 画面 + 观众」。结构可以一对一映射，但**每一格的内容都要换掉**：

| ProAct 概念 | 游戏域对应物 | 我们的现状 |
| --- | --- | --- |
| Behavioral System（流式 omni） | Omni 解说 + 收手裁判（`fast_stream.py` / `omni.py`） | 有，但退化成「1Hz 单帧旁白」 |
| 流式动作生成（flow-matching） | **不可迁移**：动作由 gamescaling 策略模型输出键鼠序列（`motor.py`） | 手=200ms 开环块 |
| Disentangled ControlNet 注入意图 | 意图 → 「动作目标/走位指令」文本注入（`executor.run(intent)` 的 instruction） | **通了但没接线**：instruction 只写日志（`motor.py:152-158`） |
| Context Encoder + 有界 memory bank | 跨轮/跨 session 的「局面摘要」：我在哪、任务到哪、哪些交互没做完、我刚试过什么 | `memory.py` 有实现但**从未被 agent 调用**（`agent.py` grep memory 零命中） |
| user analysis（ToM） | 观众想看你做什么 + 游戏内 NPC 的意图/台词层级 | 无 |
| situation tracking | 当前场景/菜单层级/对话是否在进行/未完成任务 | 仅靠每轮图片 + 6 步窗口 |
| robot action history（防重复） | 「刚才按过什么、哪些尝试失败了」 | gamescaling history 在生产路径**恒为空**（`motor.py:110-128` 无 `.record(` 调用） |
| Motivation Assessment 五维 | 五维游戏版（见 §6） | 无，决策由慢 LLM 自由发挥 |
| τ=4 / dialogue 需 5 分 | 「该不该按键/该不该说话」的门槛 | 无门槛，每轮必须推进一步（`DIRECT_SYSTEM_PROMPT` 硬规则 1） |
| action-history check 去重 | 禁止重复同一走位/同一句碎碎念/同一无进展尝试 | 无 |
| streaming cycles 连续 | 固定节拍的「想—看—做」循环，而不是「有工具调用才动」 | 无 tick，仅在工具调用期间存在 |

## 6. 五维动机 → 游戏版五维（本文档给后续实现的建议定义）

ProAct 的五维是为「人类对话者」设计的。换成游戏，建议改造成：

| 游戏版维度 | 判定问题 | 高分样例 |
| --- | --- | --- |
| **画面事件（Visual Event）** | 画面是否发生了「需要立刻反应」的变化（红血、Boss 起手、掉落物、弹窗） | 血条见底、战斗进入新阶段 |
| **任务/剧情状态（Quest State）** | 当前是否处在「必须推进」的节点（对话选项、加载、必须按键才能继续） | 对话框停在选项上 3 秒 |
| **自身意图一致性（Self Intent）** | 当前动作是否还在服务我定的目标；是否已经偏离/卡住 | 同一位置来回走 5 秒无进展 |
| **观众/社交（Audience）** | 观众是否在等你回应；是否该开口解说/该闭嘴让演出走 | 弹幕刷「往左！」 |
| **情绪与表演（Performance）** | 此刻该不该表现出惊讶/紧张/兴奋（这是"像人"的关键） | 剧情反转、第一次见 Boss |

配套的门槛建议（直接抄 ProAct 两级克制）：

- 任一分 ≥ 4 → 允许「动作层干预」（改走位/改按键策略）；
- 仅当某维 = 5 且「不在剧情演出/对话中」→ 允许「打断式行为」（主动中止当前动作、抢话、改变目标）；
- 每次干预前查 action-history：**最近 N 次已经做过的同类动作直接否决**。

## 7. 一句话结论

ProAct 的可迁移内核不是「双系统」这个壳，而是三件具体的事：
**① 用有界压缩把慢思考时延锁死；② 用五维打分 + 阈值把「该不该动手」变成可调门控；③ 用通道级 + 行为级两级去重压制重复与过度干预。**
我们的实现目前三件都没做到：慢系统无 tick、无门控、无去重，且意图总线（`intent.py`/`arbiter.py`）写好了却**从未接线**（全仓只有单测引用）。

# 让 AI 像真人一样玩游戏：分层能力模型 + 优化清单

> 前提：本文不谈「让模型更聪明」，只谈**结构上缺什么**。因为当前所有 P0 缺陷（见 `03_current_loop_defects.md`）都会先于模型能力成为瓶颈——一个 200ms 开环盲按的系统，换 GPT-7 也躲不开 Boss。

---

## 0. 先定义「像真人」是什么（可测量）

真人玩游戏的观感由五件事构成，缺一件就会「假」：

| 维度 | 人话 | 可测代理指标 |
| --- | --- | --- |
| **反应** | 该快的时候快（<250ms），该慢的时候慢 | 反应时分布（不是均值）、对突发事件的响应延迟 |
| **连贯** | 手上的动作是连续的，不是一跳一跳 | 动作序列的自相关 / 相邻动作的语义距离 |
| **有意图** | 能看出「他在干什么」，且目标会变但不乱变 | 目标保持时长分布、目标切换的触发原因可否解释 |
| **有记忆** | 记得刚才试过什么、上次怎么过的 | 重复失败率、跨会话知识复用率 |
| **有性格** | 有偏好、有情绪、有停顿、会自嘲 | 盲测：人类能否分辨真人 vs AI 的操作录像 |

最后一条是最硬的验收：**录两段 3 分钟游玩视频（一段真人、一段 AI），让 5 个人盲猜**。目前我们必输，因为「剧情跳过 + 原地抽搐 + 慢半拍」三件套已经暴露。

---

## 1. 感知层：从「每帧全屏问 VLM」到「分层注意」

**真人怎么做**：眼睛只有中心凹是高分辨率，外周只对运动/亮度突变敏感；大脑看到的是**已经解析过的语义**（"这是对话框"、"血条在掉"、"右边有东西在动"），不是像素。所以人能以极低成本维持「场景模型」。

**我们现在**：每个决策抓一张 966×760 全屏 JPEG q85（`adapter.py:351-364, 376`），整张丢给模型；无帧差、无 OCR、无区域关注、无「什么在动」。而 `pump=False` 意味着连"连续看"都没有。

**优化项**：

| # | 做法 | 为什么像人 | 成本 |
| --- | --- | --- | --- |
| P-1 | **帧差/变化检测**：低成本算相邻帧差异，输出「哪些区域在动、动了多少」 | 人的外周视觉就是变化检测器 | 低（numpy 即可） |
| P-2 | **UI 层解析**：模板/OCR 识别对话框、选项列表、血条、任务提示 | 人认出「这是选项」就不必逐字重读 | 中 |
| P-3 | **区域裁剪 + 关注点**：只把小地图/血条/对话区送模型，而不是整屏 | 中心凹 | 低 |
| P-4 | **多帧时间窗**：给模型 3–5 帧（含帧差摘要），而不是 1 帧 | 人看的是运动不是静止照片 | 低（`extra_frames` 已支持，`omni.py:344-345`，只是没用） |
| P-5 | **状态化场景模型**：维护「我现在在哪个界面/哪张图/哪个任务阶段」，图片只用于**校验**而非每次重建 | 人不会每秒重新理解自己在哪 | 中 |

> 关键洞察：**感知的目标不是"看得更清"，而是"看得更省"**。省下来的算力才有余量去做 P-4 的多帧和 P-5 的状态维护。

## 2. 反应层：从「串行 RTT」到「反射 + 预测」

**真人怎么做**：简单视觉反应 ~200–250ms；但**有预期时接近 100ms**——因为人在事件发生前就已经把动作准备好了（anticipation）。高手不是反应快，是**提前量**。

**我们现在**：抓帧 18–34ms + decide 0.34–0.61s（无上限 60s）+ 198ms 盲按 ⇒ 等效 0.5–1s+，且按键窗口内零观测（`executor.py:235-268`）。

**优化项**：

| # | 做法 | 说明 |
| --- | --- | --- |
| R-1 | **反射层（不调大模型）**：帧差 + 规则/轻量分类器触发的固定反应（血条骤降→后撤、红光闪→闪避） | 目标 <100ms，这是唯一能追上人类的路径 |
| R-2 | **动作块缩短 + 重叠**：从 198ms 盲块改成 50–66ms 小块，且**下一块决策与当前块并行**（预取下一帧） | 把开环压到可接受 |
| R-3 | **预测-验证**：动作发出时附带「预期画面变化」，下一帧校验；不符立即中断 | 人按键前有预期，这是"手眼协调"的本质 |
| R-4 | **端到端延迟预算**：明确 grab/decide/act 三段的上限并在超限时降级（例如跳过本轮决策、保持上一动作） | 现在只有局部常量，无 SLA |

> 这是最重要的一条：**当前架构把"快"定义成"更大的模型更快的 token"，但人类的快来自"更短的决策回路 + 提前量"**。反射层是唯一能落地的替代。

---

## 3. 动作层：从「33ms 键位流」到「动作原语 + 闭环微调」

**真人怎么做**：人不是逐帧生成按键，而是**调用动作原语**（走、跑、跳、闪、交互、切武器），再在原语内部做连续微调；且原语带**力度/时长/节奏**。

**我们现在**：`adapter.play_steps(steps, step_ms=33)`，只取前 6 步，长按靠 `adapter.py:707-714` 的特殊语义；无原语概念；gamescaling history 生产恒空（`motor.py:110-128` 无 `.record(`）。

**优化项**：

| # | 做法 | 说明 |
| --- | --- | --- |
| M-1 | **动作原语库**：把「走 0.5 秒 / 跳 / 交互 / 切武器」定义成带参数的宏，LLM 只选原语+参数 | 减少 LLM 到键位的语义鸿沟；也让日志可读 |
| M-2 | **修好 history 写回**：`executor` 每步 `motor.record()` | 一行代码修复「无惯性/重复动作」 |
| M-3 | **动作去重与冷却**：同类动作在 N 次内重复直接否决（ProAct 的 action-history check 移植） | 直接消除「卡墙抽搐」 |
| M-4 | **手速与节奏建模**：连点间隔、长按时长带自然抖动，而不是恒定 33ms | 录像看起来才像手，不像脚本 |
| M-5 | **动作失败感知**：动作发出后检测"角色没动/被挡住"，立即换策略 | 人卡住会换方向，不会一直顶墙 |

## 4. 决策层：从「6 步 ReAct」到「三层时间尺度」

**真人怎么做**：分三层且**大部分时间在执行，不在决策**：
- 目标层（分钟级）：「去把那把剑拿了」；
- 子目标/计划层（10s 级）：「先绕过这堆怪，从右边楼梯上去」；
- 动作层（100ms 级）：连续微调。

人只在**异常、达成、被打断**时回到上层思考。

**我们现在**：每轮 `lumine(goal)` = 一段 ≤20s 的动作，然后重新 ReAct（`agent.py:1667`），6 步预算。中间没有「执行监控」——动作跑了 20s，慢系统只拿到解说+一张图。

**优化项**：

| # | 做法 | 说明 |
| --- | --- | --- |
| D-1 | **显式目标栈**：goal / subgoal / step 三级，落盘可恢复 | `Docs/refactor/AGENT_LOOP.md` 已有目标态设计，未实现 |
| D-2 | **执行监控（progress check）**：每 2–3s 检查「是否还在朝目标前进」，偏离即中止并回报 | 现在只有 `budget_s` 到点才回来 |
| D-3 | **慢系统 tick**：即使没有工具调用，也按固定节拍（如 3–5s）更新一次「局面摘要」，而不是等下一次调用 | ProAct 的 streaming cycles |
| D-4 | **只在异常/达成/被打断时重规划** | 避免每 20s 就"重新做人" |
| D-5 | **意图总线接线**：`intent.py`/`arbiter.py` 已有完整实现，只需接 `OmniConfig.tools` + `executor.instruction` | 这是"最低成本、最高杠杆"的一项 |

> D-5 的坑：`OmniConfig.tools` 默认空（`omni.py:54`），`session.update` 只在 tools 非空时下发（`omni.py:117-119`）→ 接线时必须同时给 tools，否则模型根本不知道 `set_intent` 存在。

## 5. 克制与节律：从「必须推进」到「默认不动」

**真人怎么做**：读文本、看地图、犹豫、发呆、等演出——**大量时间什么都不按**。这是"像人"最强的信号之一：机器才会一有帧就按。

**我们现在**：提示词硬规则「每轮至少推进一步」（`agent.py:201-202`），执行器把「连续 3 次空动作」当失败（`executor.py:283-287`）。**设计与人类相反**。

**优化项**：

| # | 做法 | 说明 |
| --- | --- | --- |
| Q-1 | **五维门控（游戏版）**：见 `01_proact_framework.md` §6；任一分 ≥4 才允许动作干预，=5 且非演出态才允许打断 | 直接移植 ProAct |
| Q-2 | **dialogue lock / 演出检测**：识别对话框、过场、加载，锁定期禁止发"跳过"类按键 | `Docs/refactor/AGENT_LOOP.md` 已有设计 |
| Q-3 | **显式 `wait/observe` 工具**：让"什么都不做"成为一个合法、可解释的动作 | 现在工具面里没有 |
| Q-4 | **Speech Policy**：「该说话」8 类 /「该沉默」6 类 / 最短发言间隔 2.5–4s | `AGENT_LOOP.md` 已有清单，未实现 |
| Q-5 | **节律分层**：探索时慢（每步 1–2s）、战斗时快（反射层接管）、剧情时静（只观察） | 固定 33ms/1s/20s 是"机器的节奏" |

## 6. 记忆层：四类记忆，缺三类

**真人怎么做**（认知科学口径）：

| 类型 | 时长 | 游戏里的例子 | 我们现在 |
| --- | --- | --- | --- |
| 工作记忆 | 秒–分钟 | 「刚才那个按钮我按过了」 | 30 条消息窗口（`tui.py:50`），**截断非压缩** |
| 情景记忆 | 小时 | 「上次在这被这怪打死」 | JSONL 后端存在，但 **agent 从不调用**（`agent.py` grep memory 零命中） |
| 语义记忆 | 永久 | 键位表、游戏规则、地图 | `profiles/*/keymap.json`、`rules.md`，**且不进提示词的 memory 通道**（`prompt_builder` 参数未传） |
| 程序性记忆 | 永久 | 「闪避要按 shift+方向」变成肌肉记忆 | **完全没有**：所有动作都过 LLM |

**优化项**：

| # | 做法 | 说明 |
| --- | --- | --- |
| E-1 | **接上记忆闭环**：`build_system_prompt(memory_rules=..., memory_bindings=...)` 传参；`learn_rule` 传 memory；`learn_key` 走 `learning.learn_key` 的统一路径 | 三个断点，都是几行代码 |
| E-2 | **工作记忆改成结构化压缩**：`position / quest_stage / last_actions[5] / failed_attempts[3] / current_subgoal`，每项一句话 | 抄 ProAct 的"每层一句话" |
| E-3 | **便签接线**：注册 `write_note/read_notes/clear_notes` 三个工具（`profiles.py` 实现已完整） | 长任务中间态 |
| E-4 | **程序性记忆**：高频、稳定的动作序列（"开箱连按"、"跑图路线"）固化成原语/脚本，不再每次过 LLM | 这是"熟练玩家"和"新手"的差别 |
| E-5 | **遗忘与冲突裁决**：TTL + 衰减 + `conflicts()` 真裁决 | 现在记忆只增不减 |
| E-6 | **写回加来源与证据**：`source`（manual/fast/slow）+ `confidence` + `evidence`（截帧/时间码） | 已有 schema，但 meta 里没 key/effect 导致冲突检测永不触发 |

## 7. 情绪与性格：从「念稿人设」到「状态驱动」

**真人怎么做**：主播的碎碎念不是随机的，是**由状态驱动**的：卡关会烦躁、抽到好东西会兴奋、遇到剧情反转会惊讶；有稳定偏好（不喜欢某个角色）、有口头禅、会自嘲、会跟弹幕互怼。

**我们现在**：`SYSTEM_PROMPT`/`DIRECT_SYSTEM_PROMPT` 写了「像人一样碎碎念」（`agent.py:230-256, 184-210`），但**没有任何情绪状态变量**——所以"碎碎念"只能是念稿，观众几分钟就看出来。

**优化项**：

| # | 做法 | 说明 |
| --- | --- | --- |
| A-1 | **情绪状态机**：`valence / arousal / confidence` 三个标量，由事件更新（死亡、掉血、抽卡、剧情反转） | 状态影响语速、用词、动作激进度 |
| A-2 | **偏好表**：对角色/玩法/道具的喜好，落 profile，跨会话稳定 | 这是"人格"的锚 |
| A-3 | **表演模板 vs 即兴**：事件触发模板（"啊——"），其余即兴；避免每次都自由发挥导致"每句话都差不多" | 现在全靠自由发挥 |
| A-4 | **沉默也是表演**：紧张时不说话，只按键 | 配合 Q-4 |
| A-5 | **反模式警告**：不要在提示词里堆"你要像人一样"——没有状态支撑的拟人指令只会产生**更假**的表演 | 现在 `DIRECT_SYSTEM_PROMPT` 已接近这个反模式 |

## 8. 失败与恢复：从「终止式」到「试错式」

**真人怎么做**：会试错、会撤退、会换策略、会记住"这招不行"。**失败是人味的主要来源之一**——一个永远不犯错的玩家反而不像人。

**我们现在**：抓帧连错 3 → 终止；motor 异常 → 立即 break；空动作 3 次 → 终止；一次 502 可判死整段。无重试、无换策略、无归因。

**优化项**：

| # | 做法 | 说明 |
| --- | --- | --- |
| F-1 | **分级重试**：反射层重试 → 原语重试 → 重规划 → 放弃当前子目标（不进终止） | 现在只有"继续/终止" |
| F-2 | **失败归因写回**：`{action, context, why_failed, retry_count}` 写进工作记忆 + 情景记忆 | 直接提升「不重复犯错」 |
| F-3 | **自然犯错的边界**：允许小失误（按错、走反），但要有"发现并按回来"的动作 | 这是"人味"，但要有上限防止崩盘 |
| F-4 | **放弃与换目标**：卡关超过阈值 → 主动放弃并换目标，且说出来 | 真人会"算了我先去别处" |

## 9. 社交与直播层：观众是"第二输入"

**真人怎么做**：读弹幕、决定回不回、什么时候回、用什么语气；也会"对着观众吐槽游戏"。

**我们现在**：弹幕以「（观众弹幕…）」形式注入（`agent.py:252-253`），但无 Speech Policy、无"该不该回"的门控，且**没有把弹幕变成动作意图的通道**（观众喊"往左"不会进 `intent`）。

**优化项**：

| # | 做法 | 说明 |
| --- | --- | --- |
| S-1 | **弹幕 → 意图候选**：观众指令先进 `IntentBus`，按 confidence/urgency 与「是否在演出中」门控 | 复用已有死代码 |
| S-2 | **回复率与间隔**：不是每条都回；最短间隔 + 优先级（有人打赏/求助才优先） | Speech Policy |
| S-3 | **观众情绪感知**：从弹幕密度/情绪词估计"观众在起哄/在骂"，影响表现 | 表演层输入 |

## 11. 验收：怎么证明"更像人了"

1. **反应时分布**：突发事件的响应延迟 P50/P90（目标 P50 <250ms，靠反射层）；不是均值。
2. **动作连贯性**：相邻动作语义距离 + 重复动作率（目标：同类动作 5s 内重复率 <10%）。
3. **剧情跳过率**：在有对话/演出的场景里发出"跳过类按键"的比例（目标 <2%）。
4. **无效徘徊时长**：同一位置停留超过 8s 且无进展的次数/小时。
5. **跨会话知识复用率**：第二天开局时提示词里已包含的键位/规则条数。
6. **盲测**：3 分钟游玩录像，5 人盲猜真人/AI，目标 ≥3 人猜错（即"看不出是 AI"）。

> 这六条都是**可从现有日志算出来的**（`_diag/agent-runs/*.jsonl` 已记录 actions/t_ms/errors），不需要新埋点即可建立基线，再逐项提升。
